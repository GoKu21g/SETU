
SAHAYOGI SETU V2
Detailed Architecture, Operations & Execution Blueprint
Working Draft for Manual Review | 21 September 2026

Core proposition — Setu is the internal ecosystem control plane. It governs, administers, observes, secures and orchestrates Sahayogi without duplicating business operations already owned by BoSS or another Sahayogi product.

1. Executive Architecture
Execution test — Every material capability must support: Detect → Investigate → Decide → Authorise → Execute → Verify → Record → Learn.

1.1 Design principles
One authoritative source per domain; Setu can aggregate without owning.
Sahayogi must consume its own ecosystem through a protected internal workspace.
Exceptional internal treatment should be governance, not separate product logic.
Every privileged action needs permission, reason, audit and verification.
Automation must include retries, failures, exceptions, approvals and compensation/rollback.
Persona-aware views: business, support, engineering, security and compliance need different lenses.
Controlled operations should replace ad-hoc production database changes.
Compliance should be control/evidence based.
Operational data must correlate workspace, product, service, release, integration, event and incident.
Architecture must scale to many products, workspaces, organisations, providers and metered resources.

9. Provisioning Orchestration
Provisioning principle — Setu should know what was requested, what should exist, what actually exists, and whether the final state has been verified.
Validate workspace/account state and prerequisites.
Resolve product dependencies and plan.
Create/transition subscription.
Generate effective entitlements.
Provision product resources.
Apply organisation/user/product access.
Apply configuration and limits.
Run post-provision verification.
Emit canonical completion/failure events.
Create exception when retry policy is exhausted.
Support compensation/rollback where a partially completed workflow cannot safely continue.

17. Audit, Compliance, Risk and Privacy

Control-based model — Framework → Requirement → Control → Implementation → Evidence → Test → Finding → Remediation.
The same internal control may map to multiple frameworks. This avoids separate checkbox implementations for ISO 27001, DPDPA, GDPR and future frameworks. Exact legal/control mappings should be validated against the applicable framework version and legal advice before being treated as compliance conclusions.

24. Notification and Escalation Model
Notifications should be event/policy driven, not hard-coded independently in modules.
Channels may include in-app, email, Chat with Sahayogi/WhatsApp, Slack/Teams or other approved internal channels later.
Severity and persona determine channel and escalation.
Alert deduplication and suppression are required to avoid alert fatigue.
Every actionable notification should deep-link to the exact Setu object/exception.
Escalation timers should support acknowledgement, reassignment and management escalation.

High

Immediate multi-channel escalation and incident workflow.

28.2 Authoritative UI & App Shell Architecture (Codified in SetuV2-Layout)
The frontend client architecture is fully implemented and established in the SetuV2-Layout codebase, serving as the official reference implementation for all Setu workspaces:
1. Core Stack & Framework: Next.js (App Router) + React 19 + Tailwind CSS v4. No heavy third-party UI component libraries; every component is engineered with hand-crafted utility classes, CSS variables, and native accessibility.
2. Fluid Typography & Viewport Scaling:
   - Fluid root sizing: html { font-size: clamp(13px, min(calc(9.5px + 0.4vw), calc(5px + 1.2vh)), 17px); }
   - All spacing, typography, and card paddings ride continuously on rem units, automatically reflowing on window resizing and browser zooming without awkward jump thresholds.
   - Standardized rem media query breakpoints:
     * screen-420: min-width: 26.25rem (420px) — Compact mobile
     * screen-sm: min-width: 36rem (576px) — Small tablet / navigation mode switch
     * screen-lg: min-width: 56rem (896px) — Standard tablet / side-by-side transition
     * screen-xl: min-width: 72rem (1152px) — Standard desktop
     * screen-1366: min-width: 85.375rem (1366px) — Laptop viewport
     * screen-1440: min-width: 90rem (1440px) — Primary design desktop canvas
     * screen-2xl: min-width: 96rem (1536px) — High-resolution display
3. App Shell Structure (AppShell.tsx):
   - Full viewport dynamic container: h-dvh, overflow-hidden, bg-[var(--shell-bg)].
   - Right-edge alignment strip: 2.1rem (desktop) to 2.5rem (2xl) right gutter matching Header action buttons, dashboard main padding, and background edge filler for pixel-perfect vertical alignment at any zoom level.
   - Non-destructive state preservation: When the AI Assistant expands to fullscreen, the main dashboard column smoothly shrinks flex-grow from 1 to 0 with transition-[flex-grow,opacity] duration-300 ease-out, preserving user form drafts, scroll position, and tab state.
4. Dual-Mode Responsive Navigation (Sidebar.tsx):
   - Desktop Mode (screen-sm and above): Vertical slim icon-rail (width 5.75rem / 92px). Includes top logo linking to persona dashboard, persona-specific icon buttons (44x44px rounded-lg with group-hover:scale-105 and hover:bg-[var(--search-bg)]), a dynamic sliding left indicator pill (width 4px, rounded-full, animated via transition-all duration-300 ease-out matching offsetTop and offsetHeight of the active route), and 12px micro-labels.
   - Mobile Mode (< screen-sm): Automatically reflows into a fixed bottom navigation bar (h-16 / 4rem, fixed inset-x-0 bottom-0 z-40, bg-[var(--shell-bg)]) with horizontal touch distribution.
   - Persona-Scoped Nav Rails: Supports Founder, Engineering Lead, Compliance Officer, Technical Support Agent, and DevOps/SRE Specialist with role-filtered primary routes.
5. Universal Top Header (Header.tsx):
   - Fixed height 4.5rem (72px) with clean bottom divider line.
   - Adaptive mobile brand logo (renders only when desktop sidebar logo is hidden).
   - Fluid centered search bar (flex-1 max-w-[30rem] with min-w-0 to prevent horizontal overflow on foldable/small screens), placeholder, and keyboard shortcut hint.
   - Action cluster on right:
